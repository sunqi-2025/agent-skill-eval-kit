# 科技软件类 Agent Skill 实测评测口径（参考版）

这份清单整理自日常软件测试、代码安全排查与本地工作流 Skill 开发实践，用于判断一个面向研发/测试/运维的 Skill 是「真正能拿去干活的工具」，还是「只跑得通演示场景的提示词」。

## 一、五项核心验收门槛

### 1. 触发边界与路由精度
- 正向典型请求能稳定触发，不漏判。
- 边缘请求或相邻领域的任务不会被误抢。
- 文档里写清了「什么情况不该用本 Skill」。

### 2. 确定性逻辑下沉
- 精确计数、正则或 AST 扫描、文件比对、HTTP 契约校验和环境探活应交给脚本完成。
- 模型负责语义判断、拆解和总结，不让模型靠猜输出需要精确核对的字段。

### 3. 上下文预算与日志治理
- 执行日志排查、代码扫描或压测时，大体积原始输出必须先落盘本地文件，只把摘要、核心异常栈和文件路径返给对话。
- 较长的参考口径放进 `references/` 按需读取，避免常驻在主提示词里浪费上下文。

### 4. 代码层安全护栏
- 涉及数据库查询、接口写操作或环境变更的 Skill，默认走只读通道。
- 环境白名单、防误写拦截、入参校验和凭据脱敏必须在脚本层写死，不单靠提示词里的口头提醒。

### 5. 异常分支与脏数据鲁棒性
- 故意构造 4xx/5xx、空响应、前端瞬时提示（300–500ms Toast）、历史脏数据或缺失上下文参数去试。
- 跑不通或证据不足时必须如实报失败/阻塞，禁止顺着正常路径编造「已完成」或「测试通过」。

## 二、常见缺陷评审样例（脱敏模拟）

| 场景 | 待测 Skill 常见毛病 | 风险判定 | 整改方向 |
| :--- | :--- | :--- | :--- |
| 非激活配置误报 | 扫到 `dev/test` 样例配置里的占位密钥直接按高危泄露报出 | 高误报，拉低研发信任度 | 脚本先过滤非激活 profile 和测试目录，再做上下文复核，无实证不提单 |
| 长堆栈直接刷屏 | 排查报错时把 3,000+ 行框架日志直接输出到对话 | 上下文很快吃满，后续指令漂移 | 截断框架噪声、原文落盘，只返根因行和摘要 |
| 写操作无硬拦截 | 允许模型按自然语言直接拼 SQL 执行更新 | 高危误写（默认放行） | 代码层强制只读，写操作必须经测试白名单和显式确认 |
| 工具链静默失败 | 多轮调用外部接口拉取异步结果时漏传会话参数，返回空体仍报「成功」 | 伪通过，掩盖真实链路断裂 | 补齐 HTTP 状态码和关键业务字段非空双断言，异常强制转 `ERROR/REVIEW` |
